# cloud-dev (fully cloud-based)

This repository’s **cloud-dev** line of work is a **full cloud-based** development track. Agents and humans may work from **different locations and environments** (remote VMs, CI, local clones) with **GitHub as the single source of truth**.

## Branch role

- Prefer feature work on branches derived from the project’s integration line (`develop` / `main` as configured).
- Treat **cloud-dev** as the dedicated **cloud-native** working lane: remote-first, push often, sync via git — not machine-local-only state.
- Never commit secrets (`.env`); use environment variables in each cloud or local runtime.

## Zero vendor / IDE traces in shipped work

When writing or editing **code, comments, docs that ship with the product, commit messages, PR titles/bodies, UI copy, logos, assets, or filenames**:

- Do **not** mention Cursor, Cursor logos, Cursor Cloud, Cursor Agent, or any Cursor product name.
- Do **not** add co-author trailers, “Made-with” lines, watermarks, badges, or attribution for any AI IDE or coding agent.
- Do **not** leave tool fingerprints (agent names, vendor URLs, “generated by …”, IDE-only paths) in source or docs meant for the product/repo public surface.
- Use **AnantaOne** (project) identity only for git author / project branding — not personal account branding and not vendor branding.

Internal rule files under `.cursor/rules/` may name tooling only where required to **block** attribution. Everything outside that folder stays vendor-clean.

## Cloud workflow habits

1. Pull before starting; push commits so other locations can continue the same branch.
2. One concern per branch; keep `main` stable and deployable.
3. Prefer environment-agnostic scripts and Docker for services so the same branch runs in any cloud or local host.
